# Custom Gatekeeper

Company-context Gatekeeper for this Brenda OS deployment. It is auto-provisioned (no OAuth). Reads go through `authorizeObservation`. Writes go through `submitAction` and are simulated so later Session reads look applied until `applyAction` / `rejectAction` / `revertAction` run on the Durable Object.

Agent-facing API (`CustomSession`):

- `getDeploymentInfo()` — name and guidance from `deployment.jsonc`
- `getTopology()` — Worker names, pinned core SHA, remaining deploy blockers
- `listOfficialDocs()` — official Cloudflare OS and platform documentation
- `listSkills()` / `getSkill(id)` — curated skills in `src/company-os.ts`
- `listGlossary()` / `getGlossaryEntry(term)` — Cloudflare OS vocabulary for this deployment
- `listEstate()` / `getEstateWorker(name)` — existing Worker inventory (names and roles only)
- `fileOperatorNote(title, body)` / `listOperatorNotes()` / `getOperatorNote(id)` — durable operator notes

Workshop extras on `CustomGatekeeper`:

- `getAgentCatalog()` — bounded discovery index (skills first, then glossary, then estate)
- `getSlashCommandProvider()` — `/run-local`, `/fill-deploy-config`, and the other company skills
- `applyAction` / `rejectAction` / `revertAction` — numeric action IDs from `submitAction`

## Adapt it

Change only the pieces your integration needs:

- `src/types.d.ts`: replace `CustomSession` with the API agents and Gadgets may call. Do not mention the write pipeline in JSDoc.
- `src/types-code.ts`: keep the agent-facing declaration synchronized with `types.d.ts`.
- `src/company-os.ts`: topology, docs, skills, glossary, estate. No secrets.
- `src/notes.ts`: pending/applied overlay used to simulate writes.
- `src/custom.ts`: Session methods, catalog, slash commands, and Gatekeeper apply/reject/revert.
- `wrangler.jsonc`: add non-secret bindings/variables and a migration when adding Durable Object classes.
- `deployment.jsonc`: provide deployment values and keep the `GATEKEEPER_CUSTOM` service binding generated by `scripts/deploy.ts`.

Put API tokens and OAuth credentials in Wrangler secrets, never `wrangler.jsonc` or `deployment.jsonc`.

## Observer policy

`CustomVerifier.verify()` accepts every observer because the example returns the same low-stakes deployment text to every authenticated user. That is not a safe default for account-specific, tenant-specific, or confidential data.

A real integration must decide which observers may retain data and implement verification at that data boundary. Use upstream's [`write-gatekeeper` skill](https://github.com/cloudflare/cloudflare-os/blob/main/.agents/skills/write-gatekeeper/SKILL.md) for observer design, OAuth, URL-scoped resources, writes and simulation, hooks, and configurator UI.
